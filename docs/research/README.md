# План ресёрча

Цель фазы: до начала сборки получить ответы на вопросы, без которых нельзя проектировать систему. Задачи ведём в Linear (проект «Hackalem AI Hackathon», milestone «Ресёрч»).

## Что уже известно про данные

- Два CSV (турбина 1 и 2), шаг 10 минут, период **2023-03-11 00:00 → 2026-01-31 23:50**.
- Колонки: время, средняя скорость ветра (м/с), нормализованная активная мощность (0..1), температура (°C). Пустых ячеек нет, мощность в диапазоне 0..1 без выбросов.
- **Февраля 2026 в файлах нет** — это скрытый тестовый период. Валидироваться будем на собственных холдаутах (например, февраль 2025 и январь 2026).
- Таймзона в данных **не указана**. Казахстан перешёл с UTC+6 на UTC+5 1 марта 2024 — это нужно определить эмпирически до стыковки с прогнозами погоды.
- Пропуски: у турбины 1 нет данных 2024-05-18 → 2024-07-17 (два месяца), у обеих — 2025-10-03 → 2025-10-05. Всего 67 разрывов у T1 и 178 у T2.
- Координаты: T1 `43.645150, 78.535604`, T2 `43.643198, 78.538828` (Алматинская область, ~300 м друг от друга). Турбины ведут себя почти одинаково.
- Сезонность: зимой (ноябрь–март) средняя мощность 0.42–0.52, летом (июль–сентябрь) 0.23–0.30.

## Воркстримы

### 1. Данные и ML-модель — Akylbek
- Очистка SCADA: простои, ограничения мощности (curtailment), обледенение, залипшие датчики.
- Агрегация 10-мин → час, определение «почасовой выработки».
- Кривая мощности по данным, бейзлайны (persistence, климатология), потолок точности при идеальном прогнозе ветра.
- Стек моделей: GBDT на признаках NWP vs физическая кривая мощности; протокол rolling-origin бэктеста и метрики (nMAE, nRMSE, skill vs persistence).

### 2. Погодные данные и бэктест — Ramazan
- Источники **архивных прогнозов** (а не реанализа) по координатам: Open-Meteo Previous Runs / Historical Forecast, ECMWF Open Data, GFS-архивы и др. Семантика lead time, доступные высоты ветра, лимиты.
- Реанализ (ERA5) для обучающих признаков.
- Эмпирическое определение таймзоны SCADA через кросс-корреляцию с ERA5.
- Схема as-of бэктеста: прогноз, выпущенный в день D, на D+1…D+2, последовательно за 31.01–28.02.2026.

### 3. Агент, продукт, README, демо — Birzhan
- Архитектура агентного цикла: что делает LLM, что — детерминированные инструменты; триггеры пересчёта.
- Фреймворк (Claude Agent SDK / LangGraph / plain tool loop), логирование решений агента.
- Скелет README под чек-лист организаторов, воспроизводимость одной командой, Docker, `.env`.
- Демо: дашборд прогноз vs факт и лог рассуждений агента; ценность для рынка Казахстана (правила прогнозирования ВИЭ, штрафы за небаланс).

## Риски
- Архивные прогнозы на нужные даты недоступны или доступны не с тем lead time.
- Ошибка таймзоны сдвигает всё на 5–6 часов и убивает точность.
- «Агент», который на деле просто скрипт, — жюри оценивает соответствие заявленной логики реализации.
- README, по которому эксперты не смогут развернуть проект.
