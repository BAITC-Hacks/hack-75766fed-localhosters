# LOC-14: архив прогнозов Open-Meteo

## Запуск

Python 3.11+; проверено на Python 3.14. Окружение устанавливается из корня репозитория:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -e '.[dev]'
.venv/bin/python -m windagent.dump_weather
OPEN_METEO_CACHE_ONLY=1 .venv/bin/python -m windagent.dump_weather
.venv/bin/python -m pytest -q
.venv/bin/ruff check windagent tests
```

Все 118 ответов API входят в репозиторий: обычный повторный запуск тоже читает кеш.
Для новой сетевой выгрузки можно указать пустую директорию `--root /tmp/new-weather`.
Нельзя одновременно запускать несколько выгрузок в одну директорию.

## Интерфейс

```python
from windagent.tools.weather import single_run
response = single_run("2026-01-31T06:00")
```

`single_run(run_iso, model='ecmwf_ifs', forecast_days=4)` возвращает исходный JSON
Open-Meteo. В этой реализации поддерживается только `ecmwf_ifs`. Naive ISO-время
трактуется как UTC; ISO со смещением переводится в UTC. Принимаются циклы
00/06/12/18 без минут/секунд. `WeatherClient` позволяет переиспользовать HTTP-сессию,
задать корень кеша, координаты, бюджет запросов и явно включить офлайн-режим.

`om_get(url, params)` всегда устанавливает `timezone=UTC`, `wind_speed_unit=ms`.
Разрешены только Single Runs и Previous Runs endpoints. Ошибки 429 и 5xx повторяются
до четырёх попыток с exponential backoff (либо числовым Retry-After), задержка
ограничена 60 секундами. Другие HTTP-ошибки не повторяются. Таймауты подключения
и чтения — 10 и 60 секунд. В одной сессии максимум 190 сетевых попыток.

## Кеш и происхождение

- `.om_cache.sqlite`: локальный requests-cache, `expire_after=-1`, исключён из Git.
- `data/nwp_cache/single_runs/ecmwf_ifs/*Z.json`: 116 неизменённых ответов API.
- Рядом `*.meta.json`: URL, нормализованные параметры, fetched_at, SHA-256, grid, ключ.
- `data/nwp_cache/requests/`: ещё два ответа — Previous Runs и контрольная T2.
- `data/nwp_cache/manifest.json`: сводный индекс, контрольные суммы и результаты проверок.
- `data/nwp/single_runs_ecmwf_ifs_feb2026.parquet`: 11 136 строк (116 × 96 часов).

Переносимый JSON-кеш проверяется по ключу запроса и SHA-256 перед чтением. При
отсутствии JSON проверяется HTTP-кеш. `OPEN_METEO_CACHE_ONLY=1` запрещает сетевой
fallback; отсутствующий запрос вызывает `CacheMissError` с ключом и путём.
Тест свежего checkout копирует только JSON, запрещает HTTPAdapter.send и полностью
пересобирает Parquet. Повторная выгрузка сохраняет исходный fetched_at, а не
выдаёт время чтения кеша за время скачивания.

## Временная схема и критерий полноты

- `run_init_utc`: UTC-время инициализации модели.
- `valid_utc`: UTC-время, на которое рассчитано значение.
- `lead_h`: `(valid_utc - run_init_utc)` в часах, целое число.
- Остальные семь колонок — переменные из тикета; ветер в м/с.
- Диапазон инициализаций: 2026-01-31 00Z — 2026-02-28 18Z включительно.
- Времена прогноза могут выходить в март; по границе февраля они не обрезаются.

**Оговорка к критерию тикета:** у всех 116 запусков `wind_gusts_10m` отсутствует
на `lead_h=0`. Исходные значения сохранены, заполнение соседним часом не применяется.
Критерий «72 часа без null» проверяется на `1 <= lead_h <= 72` (8 352 строки),
где все семь переменных заполнены. Если автор тикета подразумевал `0..71`, этот
критерий буквально не выполнен: нужно согласовать горизонт, а не скрывать null.

Previous Runs `wind_speed_100m_previous_day1` за 2026-02-01 сравнен с lead 24..29
запусков 2026-01-31 00/06/12/18Z. Все 24 значения совпали, максимальная разница
для каждого блока — 0 м/с. Сравнение делается по времени, а не номеру строки.

## Две турбины

T1: 43.645150, 78.535604; T2: 43.643198, 78.538828.
Контрольный запрос T2 для 2026-01-31 00Z подтвердил общий узел
**43.620384, 78.47891**. Высота узла также сохранена в метаданных.
Для всех 116 запросов T1 проверяется неизменность координат узла.
Совпадение узла не означает идентичность локальных условий у двух турбин.

## Ограничения as-of и происхождения архива

Время инициализации не равно времени публикации. Для глобальных моделей
результат обычно доступен спустя 4–6 часов; downstream-бэктест должен применять
явную политику доступности. `fetched_at` в сентябре не даёт исторического
времени публикации февральского прогноза.

Документация Open-Meteo описывает ранний архив ECMWF IFS как Cycle 49R1 hindcasts.
Поэтому наличие run_init_utc само по себе не доказывает, что именно эти значения
публиковались в реальном времени в феврале. Это ограничение нужно учитывать
в выводах бэктеста и презентации, не подменяя архив реанализом.
